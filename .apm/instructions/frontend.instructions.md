# フロントエンド

## ドメインの判断を画面に書かない

- 画面はモデル（Lean CLI / REST）の映し。並べ替え・絞り込み・集計・可否判定・遷移先の予測を画面で行わない。
- 出し分けの根拠は View が運んでいる事実だけ。View に無い事実を画面で導出しない。足りなければ Lean の View に足す → 契約に写す → `pnpm gen:api`。
- 業務としてできない操作は出さない。ただし可否の権威はモデルで、出したボタンが拒否されたら理由をそのまま出す。
- コマンド後の遷移先・次の状態を画面で予測しない。読み直した View から決める。
- 未決（open な HS / MQ）をデザインで埋めない。モデルに無い操作を置かない（反機能一覧は `lean/<Root>/Runtime/Command.lean`）。
- 利用者が明示的に求めた絞り込みだけは許す。条件は「伏せた件数を出す」「全部を見る場所へ戻れる」。

## 口は契約 1 枚

- 外と話す口は `openapi.yaml` から生成したクライアント 1 枚（openapi-fetch + 生成型）。手書きの包み・手書きの型を置かない。契約を変えたら生成し直し、写し漏れはコンパイルエラーで出す。
- dev の相手は Lean CLI（契約を browser 内で実装する fetch を注入）。ビルドでは分岐ごと消え、dist に Lean 側のコードを入れない。
- Lean ↔ 契約の詰め替えは形の違いだけ。値の整合は golden 再生 × スキーマ検証で縛る。要求方向（コマンド）も golden の trace と突き合わせる。
- 拒否語彙（4xx の code）は契約から導出する。手書きの一覧を契約と突き合わせるテストを持つ。
- Lean が返す `state` は dev の fetch の外に出さない（React に渡さない）。「世界をやり直す」ボタンを置かない — ドメインに無い操作だから。
- コマンドが通ったら板を読み直し、結果が映ってから「できました」と言う。拒否では読み直さない（世界は変わっていない）。楽観的に画面を先に変えない。
- 401 / 403 / 404 / 5xx を「見つかりません」の一色に潰さない。期限切れはサインインし直せる導線にする。

## 認証

- 認可コード + PKCE。OIDC のエンドポイントは discovery から読む（issuer 直下に決め打ちしない）。トークンは sessionStorage、dev の世界は localStorage（人は替わる・世界は続く）。
- 名義（誰として）は画面で選ばない。クレームから読む。番号をでっち上げない。

## テスト・品質

- テストの材料は golden（モデルが吐いた JSON）。手書きの Views を組まない。スタブはドメインを再実装しない。
- テストコードも型検査の対象に入れる。リンタの警告は指摘として並べ直さず、直す。
- アクセシビリティ: キーボードだけで一巡できる、フォーカスの行方、`role="status"` / `aria-live`、コントラスト、狭い幅。遷移は `<a>` で、遷移後にフォーカスを移す。
- 見た目の根拠はトークンの 1 か所に導出として書き、色は役割で選ぶ。昼と宵の両方に足す。
- 本番の利用者向け文言に開発の構成（Lean / dev）を漏らさない。
