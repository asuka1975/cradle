# scaffold-check — 骨格を生成器に通す回帰検査

Cradle の骨格（`.apm/skills/cradle-init/assets/lean`、名前空間 `Sprout`）を `build/scaffold/lean` に写し、Gradle plugin `dev.lean2kotlin` で抽出 → 生成 → コンパイル → 生成された抽象契約テスト 7 本を InMemory 実装（`src/main`。Repository は観測モデルの一意制約を実 DB と同じく例外で守る）と具象サブクラス（`src/test`）で通す。配線は消費側と同じ形（生成器はこのリポジトリの `lean2kotlin/` を `includeBuild`。別の checkout は `LEAN2KOTLIN_HOME`）。

回し方: `cd lean2kotlin/scaffold-check && ./gradlew --no-daemon test`（elan と JDK 21 が要る。`.lake` は抽出器側 `lean2kotlin/lean/.lake` と写し側 `build/scaffold/lean/.lake` にでき、`assets/lean` の下にはできない）。

`src/generated/` はコミットする — 生成器の出力の実物スナップショットで、生成の変化が PR の diff に見える。CI は再生成して `src/generated` に差分（未追跡を含む）が無いことを確かめる。

`port/` は子プロジェクトで、外部能力の Port を持つ最小ドメイン「ロビーの来訪受付」（`port/lean`、名前空間 `Lobby`。CLI（`external` に対応する `lake exe lobby`）と環境つきの golden（`port/lean/golden/`。脇書きに環境の名前と入力列）を持ち、モックアップは持たない）を同じ経路で通す。CLI と golden は `external` の回帰素材（`payment-partial` は環境を途中で止めて `stopAt` を持つ流れの例）で、`lakefile.toml` の `defaultTargets` は lib と exe の両方を持ち、CI が `lake build lobby` と `golden-check`（`port` を `CRADLE_PROJECT_DIR` に）で再生する。Port の interface・要求と観測の型・契約テスト用モックの生成、Port を使う UseCase の契約テスト、短い名前の DomainService、上限つきの制約（`atMostOneExpected`）の回帰素材で、`port/src/test` の `WrongPortUseTest` は Port の使い方を誤った実装（呼ばない・違う要求・2 回・validate より先・失敗の握りつぶし）が生成テストで赤くなることを確かめる。決済（来訪の精算）は副作用の縦断例: 利用者の開始（`StartPaymentUseCase`）、内部入力（`Observation`）で動く配送・確定の通知・照会（`DispatchPaymentUseCase` / `ConfirmPaymentUseCase` / `InquirePaymentUseCase`。名義を受けない）、2 操作を持つ Port（`PaymentGateway`）、消費位置つきの障害契約（送る前・応答喪失・反映の commit 前）の素材で、`WrongDispatchTest` は送る印を保存する前に送る実装が 3 つの中断点で赤くなることを確かめる。`cradle.json` は `lean-check` をこの素材に掛けるためのもの。`port/src/adapterTest` は生成された Adapter の適合テスト（`kotlin-adapter-test`）に stub 相手の Adapter を配線し、`./gradlew :port:adapterContractTest` で回す（`test` の門には入らない）。`port/src/generated/` も同じくスナップショット。

`extract-fixture/` は抽出だけの子プロジェクトで、抽出器の回帰素材「倉庫の注文」（`extract-fixture/lean`、名前空間 `Depot`）に `extractLeanIr` だけを掛ける（kotlin-jvm を当てないので生成もコンパイルも無い）。IR は `diagnostics.dropped` を持ち、生成器は 1 件でも失敗にするので生成には通さない。抽出した `extract-fixture/build/lean2kotlin/lean2kotlin-ir.json` をコミット済みの `extract-fixture/expected-ir.json` と `cmp` で突き合わせる（CI も同じ）。Sprout と Lobby の IR に出ない抽出器の経路を持つ: 診断の理由（定理でない宣言の `@[contract]`・主対象に触れない契約定理・ケースを演繹できない契約定理・翻訳できない契約定理・写像できない固定形の署名・def でない宣言の `@[faultContract]`・UseCase ディレクトリの外の障害契約）、主対象の def が Int の引数や未分類の型で署名を写せないふるまい・判断への指名、名前の成分が `inst` で始まる def（inst の次が小文字の `instantRefund` / `instantQuote` は残り、大文字の `instToStringOrder.label` は除く）、名前の無い構成子の引数（形の欄名とオラクルの値の鍵。簡約で ctor 正規形にならない irreducible なふるまいの値は合成したシリアライザで直列化する）、VO と短い名前が同じ入力語彙（ふるまいの主対象と UseCase の `input` の解決。名前空間が型でない def の短い名前が 2 つの型に当たる場合も）、1 つの DomainService ファイルが 2 つの名前空間に持つ同じ葉名。回し方: `./gradlew --no-daemon :extract-fixture:extractLeanIr && cmp extract-fixture/build/lean2kotlin/lean2kotlin-ir.json extract-fixture/expected-ir.json`。抽出器の挙動を変えたら IR の差分を確かめ、同じファイルを `expected-ir.json` へ写す。
